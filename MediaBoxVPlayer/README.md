# MediaBoxVPlayer

Многооконный видеоплеер для MediaBoxManager. Каждое окно имеет собственный
декодер Qt Multimedia, очередь, состояние воспроизведения, громкость и повтор.
До 16 окон можно разместить на разных подключённых мониторах или на одном.
Видео сохраняет пропорции; свободное пространство остаётся чёрным.

Приложение запускается в пользовательском графическом сеансе. Оно продолжает
работать без окон и после закрытия последнего окна. MediaBoxManager создаёт и
настраивает окна через [JSON/TCP API v1](TCP_API.md).

В Manager откройте **Видеоэкраны**, выберите окно и примените его монитор.
Кнопка **По расписанию** включает расписание видеоканалов для этого окна;
плеер сам переключает каналы и рекламные блоки по времени. Для запуска вне
расписания выберите видеоканал в основном окне Manager и нажмите **Играть канал**:
все его файлы воспроизводятся с повтором. Подтверждённый режим и канал видны
в состоянии видеоэкрана. **Пауза** и **Стоп** возвращают окно в ручной режим;
возобновление расписания выполняется кнопкой **По расписанию**.

## Автоматический запуск из Manager

На Windows и Linux Manager при своём запуске подключается к видеоплееру.
Если локальное TCP-подключение недоступно, он запускает соседний
`MediaBoxVPlayer` с флагом `--managed` и автоматически подключается к нему.
Открывать панель видео для этого не требуется. Разрешены `localhost` и
IP-адреса loopback; удалённый видеоплеер нужно запустить отдельно.

Для локального подключения поле токена можно оставить пустым. На порту `17656`
Manager сначала использует доступный корректный токен из стандартного каталога
MediaBoxVPlayer; иначе создаёт или читает собственный защищённый `control.token`
в `<каталог настроек Manager>/managed-vplayer/<адрес>-<порт>`. Сохранённые
настройки подключения при этом не меняются. Если уже работающий плеер имеет
другой токен, укажите его явно в настройках Manager: ошибка авторизации или
версии протокола не запускает дополнительный экземпляр.

В режиме `--managed` обязательны явный `--data-dir` и loopback-адрес `--host`.
Manager передаёт секрет через `MEDIABOXVPLAYER_CONTROL_TOKEN`; требуется
64 строчных шестнадцатеричных символа. Плеер использует токен в памяти,
удаляет эту переменную из окружения и не читает и не создаёт `control.token`.
Видеоплеер и аудиоплеер используют разные каталоги и токены.

При автоматическом запуске `player.lock` и `windows.json` находятся в указанном
каталоге `managed-vplayer`. На стандартном порту `17656`, если собственного
`windows.json` ещё нет, Manager копирует его из стандартного каталога
MediaBoxVPlayer, сохраняя исходный файл. Существующий файл не заменяется;
ошибка копирования останавливает запуск и показывается в Manager.
Сохранённые окна в режиме расписания продолжают программу по текущему времени;
ручные очереди восстанавливаются остановленными. При запуске без
сохранённой конфигурации окон нет; создайте их из Manager. Плеер продолжает работать
после закрытия Manager и при ручном отключении клиента. Для повторной попытки
после устранения ошибки нажмите **Сохранить подключение** в настройках
MediaBoxVPlayer. Отключение клиента отменяет отложенный автозапуск.
Сам флаг `--managed` не меняет сохранённый режим воспроизведения.

## Самостоятельный запуск

```sh
MediaBoxVPlayer --host 127.0.0.1 --port 17656 --data-dir /path/to/vplayer-data
```

По умолчанию API доступен на `127.0.0.1:17656`. Каталог настроек выбирается
общим `StoragePaths::Application::VideoPlayer`: Windows —
`%ProgramData%/MediaBox/MediaBoxVPlayer`, Linux — `/etc/mediabox/mediaboxvplayer`.
Пользователю требуются права записи в этот каталог; для локального запуска
можно указать доступный каталог через `--data-dir`.

В каталоге самостоятельного плеера находятся `control.token` (64 шестнадцатеричных символа),
`windows.json` и блокировка `player.lock`. Один каталог нельзя использовать
двумя экземплярами одновременно. Токен создаётся общим с аудиоплеером кодом
с ограничением прав файла; у видеоплеера собственный токен. В настройках
MediaBoxManager указываются адрес, порт и этот токен. TCP не шифруется:
удалённое подключение рассчитано на доверенную сеть или защищённый туннель.

Двойной щелчок левой кнопкой по видео переключает полный и обычный режим.
`F11` делает то же самое, `Esc` возвращает обычный режим. Геометрия обычного
окна сохраняется отдельно для мониторов на время работы процесса. Закрытие
окна останавливает его видео и скрывает окно, сохраняя конфигурацию. `play`,
`load` с `autoplay: true`, `schedule`, `playChannel` или повторная настройка окна показывают его снова.
Для удаления определения используется `removeWindow`.

Идентификатор монитора вычисляется из имени, производителя, модели и серийного
номера, без зависимости от индекса в списке. Для одинаковых идентификаторов
оборудования добавляется суффикс. У мониторов без уникального серийного номера
стабильное различение после перестановки портов не гарантируется; оператор
может выбрать монитор заново. Пустой `screen` означает текущий основной экран.

Если выбранный монитор отключён, только связанные с ним окна останавливаются
и скрываются; их `actualScreen` становится пустым. На другом мониторе эти
окна не запускаются. Когда монитор возвращается, окна показываются: активное
расписание продолжается по текущему времени, ручной режим остаётся остановленным.
Для пустого `screen` используется новый
основной монитор. Конфигурация с неизвестным монитором отклоняется целиком.

Окна, очереди, выбранные дорожки, громкость, mute, repeat, принятые расписания и
режим каждого окна сохраняются атомарно в `windows.json` версии 2. Файлы версии 1
по-прежнему читаются. После перезапуска режим `schedule` самостоятельно выбирает
канал по текущему времени, включая полные сутки и ночные окна. `mute` сохраняется;
позиция прежнего трека не восстанавливается. Команды **Пауза**, **Стоп** и ручной
запуск сохраняют ручной режим, поэтому такие окна после перезапуска остановлены.
Принятое ранее расписание остаётся доступным для команды **По расписанию**.
Недоступные медиафайлы пропускаются при восстановлении; остальные элементы
очереди и окна сохраняются, а `restoreError` конкретного окна объясняет пропуск.
Сам файл настроек при восстановлении не переписывается. Повреждённый формат
`windows.json` приводит к ошибке запуска с диагностикой, без перезаписи файла.

Ошибки сохранения не скрываются: TCP возвращает `persistence_error` с фактическим
состоянием уже применённой команды, а `status.persistenceError` сообщает о
неудаче (включая переключение мышью). Изменения действуют в текущем процессе,
но не гарантированы после перезапуска, пока последующая запись не пройдёт.

Для воспроизведения используется системный Qt Multimedia backend. Наличие
аудиоустройства не обязательно: при его отсутствии видео идёт без звука.
Поддержка кодеков зависит от сборки Qt и платформы. Пути в очереди должны быть
абсолютными путями к читаемым локальным файлам на компьютере видеоплеера.

## Сборка и проверки

Требуются CMake 3.28+, C++23 и Qt 6.12 с Core, Gui, Widgets, Network,
Multimedia и MultimediaWidgets; для тестов — Qt Test. Обычная сборка
репозитория создаёт MediaBoxVPlayer вместе с менеджером и аудиоплеером.
Возможна отдельная сборка (включает общую библиотеку и аудиоплеер):

```sh
cmake -S MediaBoxVPlayer -B build-vplayer -DCMAKE_PREFIX_PATH=/path/to/Qt/6.12
cmake --build build-vplayer
```

CMake плеера не создаёт тестовых целей, в том числе при `BUILD_TESTING=ON`.
Для сборки и запуска тестов выполните из корня репозитория в PowerShell:

```powershell
.\agent_build\build.ps1 -WithTests
```

`MediaBoxVPlayer_service` проверяет независимость окон, очереди, ошибки
валидации, сохранение и восстановление, TCP и двойной клик на поверхности
видео. Тесты используют подменяемый декодер, чтобы проверять протокол без
аудиоустройства. Проверку декодирования реального видео и размещения на
физических мониторах следует выполнять в целевом графическом сеансе.
