# Windows: служба SCM

MediaBoxPlayer реализует собственный вход в Service Control Manager. Ключ `--service` предназначен только для запуска зарегистрированной службы. Без него плеер можно запускать из консоли для проверки аудиоустройства и API.

Соберите и установите плеер вместе с Qt Multimedia и его зависимостями. Поместите установленный каталог в стабильное место, например `C:\Program Files\MediaBoxPlayer`. У пользователя `LocalService` должен быть доступ на чтение и выполнение к этому каталогу; каталог сборки внутри профиля разработчика может быть недоступен. Не перемещайте исполняемый файл после регистрации службы.

В PowerShell от администратора, из корня репозитория:

```powershell
.\MediaBoxPlayer\deploy\windows\install-service.ps1 -ExecutablePath 'C:\Program Files\MediaBoxPlayer\bin\MediaBoxPlayer.exe' -Start
Get-Service MediaBoxPlayer
Stop-Service MediaBoxPlayer
Start-Service MediaBoxPlayer
```

Скрипт регистрирует службу `MediaBoxPlayer` от `NT AUTHORITY\LocalService`, автоматический запуск и перезапуск при ошибках. Перед регистрацией он создаёт отдельный каталог `%ProgramData%\MediaBox\MediaBoxPlayer` с закрытым ACL: полный доступ у SYSTEM/Administrators, изменение у LocalService. Доступ обычных пользователей к токену управления не предоставляется. Для повторной установки существующий каталог должен сохранять эти закрытые права; скрипт отказывается менять права произвольного существующего каталога. Параметры `-DataDirectory` и `-Port` позволяют задать другой отдельный каталог и порт.

Закрытый ACL настраивает скрипт установки службы. Обычный запуск плеера из консоли создаёт каталог с унаследованными правами; после такого запуска скрипт может отказаться использовать уже существующий каталог. Поэтому сначала установите службу, а для отдельной консольной проверки задайте другой каталог через `--data-dir`. Для использования уже созданного каталога администратор должен отдельно настроить описанные выше закрытые права; скрипт не меняет их автоматически.

При создании нового токена плеер задаёт самому файлу закрытый ACL до записи: текущая учётная запись процесса, SYSTEM и Administrators. Права существующего токена и родительского каталога при обычном запуске не меняются.

Установщик Manager заменяет явное правило группы Users на корне MediaBox, не предоставляя удаление дочерних каталогов и не наследуя это правило на Player. Права других групп и родительских каталогов сохраняются. Скрипт службы проверяет права самого каталога Player; для нестандартных ACL ProgramData администратор отдельно проверяет, что другие пользователи не могут переименовать или подменить его через родительский каталог.

В свойствах службы или `sc.exe qc MediaBoxPlayer` можно проверить сохранённую команду. Пример её значения:

```text
"C:\Program Files\MediaBoxPlayer\bin\MediaBoxPlayer.exe" --service --data-dir "C:\ProgramData\MediaBox\MediaBoxPlayer" --listen 127.0.0.1 --port 17655
```

Служба сообщает SCM состояние `RUNNING` после инициализации движка и API. STOP/SHUTDOWN вызывают штатное завершение Qt; команда остановки, пришедшая во время старта, также учитывается. Ошибка запуска/работы, выраженная ненулевым кодом завершения процесса, передаётся SCM как service-specific error. Отдельная ошибка декодирования трека не считается падением службы и доступна через API.

Windows запускает службы в Session 0. Видимость и работа аудиоустройств через Qt/WASAPI зависят от драйвера, аудиослужб Windows и учётной записи; служба не наследует устройство и аудиосессию вошедшего пользователя. Поэтому установку требуется проверять воспроизведением на целевой машине. Успешный статус SCM означает готовность процесса и API, а доступность звука подтверждается реальным воспроизведением. Если устройство недоступно в Session 0, смена учётной записи сама по себе не гарантирует исправления; потребуется поддерживаемое драйвером устройство либо отдельная архитектура вывода звука в пользовательской сессии.

Для обновления остановите службу, замените плеер вместе с согласованными зависимостями и запустите снова. Для удаления регистрации:

```powershell
.\MediaBoxPlayer\deploy\windows\uninstall-service.ps1
```

Скрипт удаления сохраняет исполняемые файлы и токен. Очередь хранится в памяти;
после нового запуска Manager должен загрузить её заново.
