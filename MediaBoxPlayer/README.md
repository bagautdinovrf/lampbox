# MediaBoxPlayer

Фоновый аудиоплеер **0.2.0** на C++23 и Qt 6.12. Интерфейса нет; очередь и
воспроизведение управляются через JSON/TCP API из MediaBoxManager.
Подключение настраивается в разделе «Настройки», очередь и воспроизведение —
в панели «Управление плеером»; см. [инструкцию Manager](../README.md#подключение-mediaboxplayer).

Клиент реализован по [полной спецификации TCP API](TCP_API.md): формат сообщений, команды, ошибки,
переподключение, примеры и критерии приёмки клиента.

Единственный канал управления работающим плеером — **TCP**, одинаковый на Windows,
Linux и Android. MediaBoxManager подключается к адресу и порту плеера и передаёт
все команды, настройки воспроизведения и запросы состояния через этот канал.
Для управления не требуется запускать команды ОС, передавать Android Intent,
изменять файлы или читать реестр. Параметры командной строки задают только
первичный запуск процесса, его режим и сетевую точку подключения. На Windows
и Linux Manager умеет автоматически запустить локальный плеер, если TCP-сервер
ещё недоступен; дальнейшее управление остаётся через TCP.

Плеер воспроизводит доступные ему локальные аудиофайлы через `QMediaPlayer` и
`QAudioOutput`: очередь, пауза, остановка, перемотка, переходы, громкость,
отключение звука и повтор. Используется системное аудиоустройство по умолчанию.
Поддержка MP3, WAV, FLAC, Ogg и других форматов зависит от мультимедийных плагинов
Qt и кодеков платформы. Видео и сетевые URL не поддержаны контрактом плеера.

## Фоновый запуск

| Платформа | Механизм | Инструкция |
| --- | --- | --- |
| Windows | Служба SCM, `--service`, обработка STOP/SHUTDOWN | [Установка службы](deploy/windows/README.md) |
| Linux | Демон под пользовательским systemd, SIGTERM/SIGINT | [systemd unit](deploy/linux/README.md) |
| Android | QtService + QAndroidService, foreground service `mediaPlayback`, без Activity | [Сборка APK и запуск](android/README.md) |

Android требует системного уведомления для длительного фонового воспроизведения.
CPU wake lock удерживается во время воспроизведения, загрузки и переходов между
треками. Ограничения фонового запуска Android действуют и для этого сервиса.
На Windows доступ к аудиоустройству из Session 0 нужно проверять на целевой
машине; готовность службы и API сама по себе не подтверждает звук.

Установка и первичный запуск службы относятся к настройке ОС. TCP-соединение
возможно после запуска процесса. Команда `stop` останавливает воспроизведение,
сохраняя службу и TCP-сервер доступными для следующей команды `play`.

На desktop обычный запуск оставляет процесс в основном потоке без окна:

```sh
MediaBoxPlayer --listen 127.0.0.1 --port 17655
```

### Автоматический запуск из Manager

На Windows и Linux Manager при недоступном локальном TCP-подключении запускает
`MediaBoxPlayer` из своего каталога с флагом `--managed`. Это фоновый процесс
без окна, работающий от текущего пользователя. После закрытия Manager он
продолжает воспроизведение; следующие подключения читают его текущее состояние.
Установка службы и административные права для такого запуска не требуются.

Автозапуск разрешён для `localhost` и буквальных IP-адресов loopback. Manager
сначала пробует TCP-подключение; отказ соединения или тайм-аут подключения
разрешают запуск. Неверный токен, несовместимый протокол или разрыв уже
установленного соединения сами по себе не запускают новый процесс. Удалённый
плеер и Android-сервис запускаются отдельно.

Manager передаёт `--listen`, `--port` и отдельный `--data-dir` в
`<каталог настроек Manager>/managed-player/<адрес>-<порт>`. Секрет передаётся
через переменную окружения `MEDIABOXPLAYER_CONTROL_TOKEN`, без аргумента
командной строки. В режиме `--managed` плеер использует этот токен в памяти,
не читает и не создаёт `control.token`; файл блокировки остаётся в `--data-dir`.
Токен должен содержать 64 строчных шестнадцатеричных символа. Сам Manager
хранит свой токен в защищённом `control.token` управляемого каталога или
использует доступный токен обычного локального плеера. Настройки подключения
Manager не перезаписываются.

При пустом токене Manager сначала пробует прочитать стандартный `control.token`
обычного плеера, если выбран порт `17655`. Если файл отсутствует, недоступен
или некорректен, используется собственный защищённый токен Manager. Уже
работающая служба с другим токеном вернёт ошибку аутентификации: для неё нужно
явно указать правильный токен в настройках Manager.

`--managed` требует явно заданного `--data-dir` и loopback-адреса `--listen`;
сочетание с `--service` в Windows отклоняется. На Android этого режима нет.
Сам запуск создаёт пустую очередь и не начинает музыку автоматически.

### Каталог данных обычного плеера

Каталог должен быть доступен учётной записи плеера. Каталог настроек по умолчанию:

| Платформа | Каталог |
| --- | --- |
| Windows | `%ProgramData%\MediaBox\MediaBoxPlayer` |
| Linux | `/etc/mediabox/mediaboxplayer` |
| Android | `files/mediabox/mediaboxplayer` в закрытом каталоге приложения |

Плеер создаёт случайный `control.token` и блокировку `player.lock` в своём
каталоге настроек. Перед первым запуском в Linux администратор должен
[подготовить каталоги](deploy/linux/README.md) для учётной записи плеера.
`--data-dir` переопределяет каталог токена и блокировки. При запуске без
`--data-dir` старый токен копируется
из прежнего `QStandardPaths::AppLocalDataLocation`, только если нового ещё нет;
в Windows сначала проверяется `%ProgramData%\MediaBox\Player`.
Исходный токен сохраняется. Перенос токена службы Windows описан в
[инструкции установки](deploy/windows/README.md).
Второй процесс с тем же каталогом данных или занятым адресом/портом завершится
с ошибкой. Логи идут в stderr (в Linux — журнал systemd); ошибки воспроизведения
также доступны в `status.error`. Токен в журнал не выводится.

Очередь, позиция, громкость, режим повтора и принятый снимок расписания хранятся
в памяти. После перезапуска плеера Manager считывает новое состояние;
воспроизведение нужно включить явно. Текущие каналы и реклама исполняются
автономно через команды `setSchedule`, `schedule` и `playChannel`.
Публикация неизменяемых снимков `schedule-v1`, сохранение runtime и импорт
старых расписаний самим плеером остаются отдельными этапами.

## API управления v1

TCP по умолчанию слушает **127.0.0.1:17655**. Каждая команда — один UTF-8 JSON
объект, завершённый `\n`; ответ имеет такое же обрамление. Одно соединение может
передать несколько команд. Ответы приходят в порядке запросов. Подписок и
незапрошенных событий пока нет: Manager опрашивает `status`.

Каждый запрос содержит `protocolVersion: 1`, `token` из файла `control.token`
и `command`. Необязательный `id` (строка, число или null) возвращается без
изменений. Неизвестные поля и неправильные типы отклоняются. Максимум одного
запроса — 1 MiB вместе с завершающим переводом строки; одновременно доступны
16 подключений; неактивное подключение закрывается через 30 секунд.

Разрыв TCP-соединения не останавливает музыку и не сбрасывает очередь или настройки.
После переподключения Manager запрашивает `status` по TCP, чтобы получить текущее
состояние. Токен передаётся в каждом запросе, включая запросы нового соединения.

В обычном режиме токен создаётся один раз и сохраняется при перезапусках.
Unix-файл имеет права 0600; установочный Windows-скрипт ограничивает ACL каталога LocalService и
администраторами. Передача токена будущему Manager выполняется доверенным
способом при настройке станции. Android Manager не может читать закрытые файлы
другого APK; механизм выдачи токена для production интеграции ещё потребуется.

`--listen` позволяет выбрать другой IP. Сам TCP-протокол не шифрует трафик;
для управления через сеть используйте защищённый туннель/VPN. Доступ к токену
даёт управление очередью и воспроизведением доступных службе файлов.

Пример запроса:

```json
{"protocolVersion":1,"id":"load-1","token":"<64 hex characters>","command":"load","paths":["C:/Media/music/Трек 1.mp3","C:/Media/music/Трек 2.flac"],"autoplay":true}
```

| `command` | Дополнительные поля | Поведение |
| --- | --- | --- |
| `status` | — | Текущее состояние и очередь |
| `load` | `paths`, необязательные `startIndex` (0), `autoplay` (false) | Атомарно заменить очередь и выбрать трек |
| `enqueue` | `paths` | Добавить файлы; пустая очередь получает первый выбранный трек без автозапуска |
| `play` | — | Запустить выбранный трек или продолжить после паузы |
| `pause` | — | Приостановить; отменить ещё не подтверждённый старт/переход |
| `stop` | — | Остановить и сбросить позицию, сохранить очередь и выбранный трек |
| `next`, `previous` | — | Сменить трек; продолжить, если воспроизведение было запрошено |
| `seek` | `positionMs` | Позиция в миллисекундах, не больше известной длительности |
| `volume` | `value`: целое 0–100 | Изменить громкость |
| `mute` | `value`: boolean | Включить/выключить mute |
| `repeat` | `mode`: `off`, `all`, `one` | Повтор очереди или одного трека |
| `clear` | — | Остановить и удалить очередь |
| `playChannel` | `name`, `paths`, `volume` | Ручной запуск всего канала, повтор `all` |
| `setSchedule` | `schedule` | Атомарно заменить снимок без смены режима |
| `schedule` | необязательный `schedule` | Включить расписание с новым или ранее принятым снимком |

`paths` — непустой массив абсолютных путей к существующим читаемым файлам на
машине плеера. Относительные пути, URL, каталоги, отсутствующие файлы и null
не принимаются. Максимум 1000 записей в очереди, длина пути — до 4096 символов.
Вся новая очередь проверяется до изменения текущего воспроизведения.

`repeat: off` останавливается в конце; `all` начинает очередь сначала; `one`
повторяет закончившийся трек. Ручной `next` не учитывает `one` и переходит к
следующему; на последнем треке без `all` останавливается. `previous` на первом
остаётся на нём, а при `all` переходит к последнему. Навигация с паузы выбирает
трек в остановленном состоянии.

Ошибки декодирования и исчезнувшие после загрузки файлы пропускаются при
запрошенном воспроизведении. Повтор `all` не создаёт бесконечного цикла ошибок:
если все записи неудачны, плеер остаётся в `error`. Команды остановки, паузы,
смены очереди и навигации отменяют отложенные автоматические переходы.

Успешный ответ имеет `ok: true` и `status`. Пример:

```json
{"protocolVersion":1,"id":"s-1","ok":true,"status":{"state":"playing","playbackRequested":true,"queue":["/srv/music/track.wav"],"currentIndex":0,"currentTrack":"/srv/music/track.wav","positionMs":1234,"durationMs":10000,"volumePercent":70,"muted":false,"repeat":"off","error":""}}
```

Состояния: `stopped`, `loading`, `playing`, `paused`, `error`. `playing` и
позиция приходят от аудиобэкенда; `loading` означает ожидание его подтверждения.
`playbackRequested` отражает намерение воспроизводить и остаётся true при
переходах. `currentIndex` равен −1 при пустой очереди; неизвестная длительность — 0.
`ok: true` подтверждает принятие команды, а не физическое звучание: последующая
ошибка декодера/устройства появится в состоянии. Даже синхронная ошибка запуска
может вернуть `ok: true` с `state: error`.

Ошибочный ответ содержит `ok: false`, `error: {code, message}`, `protocolVersion`
и переданный корректный `id`. Ошибки команд также включают актуальный `status`;
ошибки аутентификации/формата его не раскрывают. Коды: `invalid_json`,
`invalid_request`, `unauthorized`, `unsupported_protocol`, `request_too_large`,
`unknown_command`, `invalid_arguments`, `invalid_path`, `empty_queue`.

## Сборка и проверки

Нужны CMake ≥ 3.28, компилятор C++23 и Qt ≥ 6.12 с **Core, Network, Multimedia**.
Для тестов нужен Qt Test. Плеер собирается как самостоятельно, так и существующим
корневым CMake вместе с Manager. Установите Qt Multimedia в выбранный комплект Qt;
исполняемому файлу нужны мультимедийные плагины и их кодеки, а не только Qt DLL.

Пример отдельной Windows-сборки в окружении MSVC x64:

```powershell
cmake -S .\MediaBoxPlayer -B .\build\MediaBoxPlayer -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="C:\Qt\6.12.0\msvc2022_64"
cmake --build .\build\MediaBoxPlayer
cmake --install .\build\MediaBoxPlayer --prefix .\build\MediaBoxPlayer-install
```

На Linux команды аналогичны. Регистрация службы/демона выполняется отдельно по
платформенным инструкциям выше; `cmake --install` сам службу не запускает.
Для генератора с несколькими конфигурациями добавьте `--config Release` к сборке
и установке. Android собирается отдельно от Manager.

CMake плеера не создаёт тестовых целей, в том числе при `BUILD_TESTING=ON`.
Для сборки и запуска тестов выполните из корня репозитория:

```powershell
.\agent_build\build.ps1 -WithTests
```

Автоматические тесты проверяют очередь с управляемым аудиобэкендом, валидацию,
повтор и ограничение ошибок, TCP-аутентификацию/обрамление запросов, реальный
запуск процесса и блокировку второго экземпляра. На Unix проверяется штатное
завершение по SIGTERM. `--version` и `--help` работают без запуска аудиодвижка.
Фактическое воспроизведение, SCM и Android lifecycle дополнительно проверяются
на соответствующих устройствах.
