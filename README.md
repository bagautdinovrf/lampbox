# MediaBoxManager

MediaBoxManager — редактор музыкальных и рекламных расписаний с управлением
фоновым аудиоплеером MediaBoxPlayer и многооконным видеоплеером MediaBoxVPlayer
по TCP. Для каждого видеоокна выбираются физический экран и отдельный плейлист.
Плееры поддерживают ручной запуск каналов и автономное исполнение текущих
расписаний, переданных Manager по TCP. Все три приложения собираются через CMake на Qt 6 и C++23.

## Архитектура редактора

| Цель CMake | Ответственность |
| --- | --- |
| `MediaBoxScheduleCore` | Типизированные правила, общая проверка, расчёт плана и воспроизводимых минут рекламы; только Qt Core |
| `MediaBoxScheduleStorage` | Версионированный проект JSON, однократный импорт старых расписаний, атомарная запись и восстановление операций с каталогами |
| `MediaBoxMediaLibrary` | Чтение метаданных и фоновый импорт с прогрессом и отменой |
| `MediaBoxPlayerClients` | TCP-клиенты аудио- и видеоплеера |
| `MediaBoxManagerApplication` | Операции над целыми правилами, состояние станции, настройки и модели Qt Core |
| `MediaBoxManagerUi` | Окна, диалоги, делегаты и оформление Qt Widgets |

Редактор и превью используют общие правила: частота рекламы — 1–5 выходов
в час, точные минуты — `00m,30m`, `*` отключает выход. Изменение громкости
сохраняет назначенные минуты; для новых временных правил расчёт воспроизводим.
Превью показывает план, а состояние плеера поступает отдельно по TCP.

Загрузка расписания не удаляет каналы и медиафайлы. Повреждённые строки
диагностируются до замены состояния в памяти; пока загрузка не исправлена,
изменения такого расписания блокируются. Сохранение передаёт правило целиком
и сообщает об ошибке, сохраняя предыдущие данные.

Все расписания станции хранятся в `project.json`: `format` —
`mediabox.manager-project`, `schemaVersion` — `1`. Документ содержит музыкальные,
видео- и рекламные правила со стабильными UUID, календарными массивами и
явным режимом рекламных выходов. Назначенные минуты частотной рекламы
сохраняются в `preparedMinutes` того же документа. Дни недели записываются
как 0–6, где 0 — воскресенье.

При отсутствии JSON редактор однократно переносит `timetable/timetable`,
`timetable/vtimetable` и `timetable/advertView`; опубликованные минуты рекламы
берёт из `timetable/adverttable`, если они соответствуют правилу. Исходные
файлы сохраняются. Повреждённый JSON или неизвестная версия вызывают ошибку;
автоматического возврата к старым файлам нет. Генераторы CSV/cron/XML удалены,
старые файлы после переноса больше не обновляются.
Неподдерживаемые условия старого формата, включая ненулевой порядок рекламных
выходов, останавливают перенос с указанием файла и строки; частичный проект
при этом не создаётся.

Сохранение использует `QLockFile` и `QSaveFile`. Операции над каталогами каналов
защищены журналом восстановления: после прерывания согласуется состояние
каталога и JSON. [Проект schedule-v1](Documentation/schedule-v1/README.md)
с публикацией неизменяемых снимков и исполнением расписаний плеерами остаётся
отдельным этапом.

Импорт сканирует файлы, читает метаданные и копирует блоками в рабочем потоке.
После завершения интерфейс получает один снимок медиатеки. Отмена сохраняет
уже добавленные файлы и убирает незавершённую временную копию; существующие
файлы с совпадающим именем не перезаписываются. Пока идёт импорт, изменение
каталогов через редактор заблокировано; воспроизведение и навигация доступны.

Тесты `schedulecore`, `schedulepersistence` и `mediaimport`
проверяют эти границы без зависимости от Qt Widgets и Multimedia.

## Сборка в Windows

Текущая установленная версия Qt: **6.12.0**, комплект
`C:\Qt\6.12.0\msvc2022_64`. Для него нужен Visual Studio 2022 с компонентами
«Разработка классических приложений на C++» и Windows SDK. Сборка требует
CMake 3.28 или новее и Ninja; инструменты из `C:\Qt\Tools` подходят.

Из корня репозитория выполните в PowerShell:

```powershell
.\agent_build\build.ps1
```

Скрипт выбирает последнюю установленную версию Qt с комплектом MSVC x64
в `C:\Qt`, настраивает окружение компилятора и собирает приложения Release.
Корневой CMake и CMake подпроектов собирают только приложения и библиотеки:
`BUILD_TESTING=ON` не подключает тесты. Для их сборки и запуска CTest
используйте скрипт с параметром `-WithTests`.
Результаты находятся в `agent_build\build\bin`: `MediaBoxManager.exe`,
`MediaBoxPlayer.exe`, `MediaBoxVPlayer.exe`; журналы — в `agent_build\logs`.

```powershell
# Сборка Debug и тесты
.\agent_build\build.ps1 -Configuration Debug -WithTests

# Сборка и готовая папка с Qt DLL и плагинами
.\agent_build\build.ps1 -Deploy

# Сборка и установщик Inno Setup 6
.\agent_build\build.ps1 -Installer

# Явный выбор комплекта Qt
.\agent_build\build.ps1 -QtRoot C:\Qt -QtVersion 6.12.0 -QtKit msvc2022_64
```

Полный список параметров и дополнительные примеры находятся в
[agent_build/README.md](agent_build/README.md).

## CMake и Qt Creator

В Qt Creator откройте корневой `CMakeLists.txt` и выберите комплект Qt 6.12
MSVC 2022 x64. CMake автоматически обрабатывает Qt MOC, `.qrc` и
ресурс значка Windows. Стандарт C++23 обязателен; для установленного MSVC
CMake включает `/std:c++latest`.

Можно использовать CMake напрямую из **x64 Native Tools Command Prompt for VS 2022**
с CMake и Ninja в `PATH`:

```powershell
cmake -S . -B agent_build/build -G Ninja -DCMAKE_PREFIX_PATH=C:/Qt/6.12.0/msvc2022_64 -DCMAKE_BUILD_TYPE=Release
cmake --build agent_build/build --parallel
cmake --install agent_build/build --prefix agent_build/deploy/Release
```

Для сборки и запуска тестов используйте `agent_build/build.ps1 -WithTests`.
CTest настраивает путь к DLL Qt автоматически. Для ручного запуска исполняемых
файлов из папки сборки добавьте `C:\Qt\6.12.0\msvc2022_64\bin` в `PATH`.
Основной скрипт настраивает этот путь автоматически. Для генераторов с несколькими
конфигурациями добавьте `--config Release` к сборке и установке и `-C Release` к CTest.

Тесты проверяют редакторы расписания, кириллицу в именах каналов и аудиофайлов,
чтение и запись метаданных TagLib, ресурсы интерфейса, распределение рекламы
и команду версии. Текстовые отчёты QtTest сохраняются в `agent_build/build/tests`.

## Зависимости

Qt-компоненты MediaBoxManager: Core, Gui, Widgets, Network; MediaBoxPlayer
использует Core, Network, Multimedia. Для MediaBoxVPlayer нужны Core, Gui,
Widgets, Network, Multimedia и MultimediaWidgets. Для
`agent_build/build.ps1 -WithTests` также нужен Test.
Исходный код приложения и тесты используют C++23 без расширений компилятора.

TagLib **2.3.2** собирается статически через CMake FetchContent из
[официального архива выпуска](https://github.com/taglib/taglib/releases/download/v2.3.2/taglib-2.3.2.tar.gz),
проверяемого по SHA-256. Это последний стабильный выпуск на 4 октября 2026 года;
версия закреплена для воспроизводимой сборки. Архив содержит необходимую
зависимость utf8cpp **4.2.0** (только заголовочные файлы), поэтому отдельно
скачивать её не требуется. Первый запуск конфигурации требует интернета;
последующие используют кэш в каталоге сборки. Внешний zlib и C bindings TagLib
отключены.

Для сборки без сети заранее распакуйте указанный архив выпуска TagLib 2.3.2
(включая `3rdparty/utfcpp`) и задайте
`-DMEDIABOXMANAGER_TAGLIB_SOURCE_DIR=C:/deps/taglib-2.3.2` при конфигурации CMake.

## Запуск

На станции MediaBox могут работать три программы: MediaBoxManager — редактор,
MediaBoxPlayer — аудиоплеер, MediaBoxVPlayer — видеоплеер.
MediaBoxManager запускается как самостоятельное приложение.
Настройки приложений отделены от общих файлов станции:

| Платформа | MediaBoxManager: настройки | MediaBoxPlayer: настройки | Общие файлы |
| --- | --- | --- | --- |
| Windows | `%ProgramData%\MediaBox\MediaBoxManager` | `%ProgramData%\MediaBox\MediaBoxPlayer` | `%ProgramData%\MediaBox` |
| Linux | `/etc/mediabox/mediaboxmanager` | `/etc/mediabox/mediaboxplayer` | `/etc/mediabox` |
| Android | `files/mediabox/mediaboxmanager` | `files/mediabox/mediaboxplayer` | `files/mediabox` внутри своего приложения |

При самостоятельном запуске MediaBoxVPlayer хранит собственные `control.token`, `windows.json` и блокировку
`player.lock` в `%ProgramData%\MediaBox\MediaBoxVPlayer` (Windows) или
`/etc/mediabox/mediaboxvplayer` (Linux). Параметр `--data-dir` позволяет выбрать
другой каталог. Многооконный видеоплеер предназначен для настольной графической
сессии Windows/Linux; таблица путей Android относится к Manager и аудиоплееру.

В Linux каталоги общесистемные: перед первым запуском администратор
[подготавливает их](MediaBoxPlayer/deploy/linux/README.md) для пользователя,
запускающего Manager и аудиосессию Player. Журналы Manager сохраняются в
`/etc/mediabox/mediaboxmanager`, токен и блокировка Player — в
`/etc/mediabox/mediaboxplayer`. Если каталоги недоступны для записи, приложение
сообщает об ошибке; перехода на пользовательские пути XDG нет. Прежние настройки
и данные текущего пользователя используются только как источники переноса.
В Android `files` — закрытый каталог приложения; разные APK не получают доступ
к каталогам друг друга. В Windows и Android журналы Manager хранятся в его каталоге.

Manager хранит `MediaBoxManager.conf` в своём каталоге настроек независимо от
места запуска EXE. При первом запуске он копирует прежний конфиг, только если
нового ещё нет. Приоритет источников в Windows:
`%ProgramData%\MediaBox\MediaBoxManager.conf`, прежний
`QStandardPaths::AppConfigLocation`, затем `MediaBoxManager.conf`
рядом с приложением. На остальных платформах проверяются те же источники без
Windows ProgramData. Исходный конфиг сохраняется; режим хранения настроек рядом
с EXE больше не выбирается автоматически.

Установщик Windows предоставляет обычным пользователям изменение каталога
Manager и общего каталога `media`. В корне MediaBox разрешены чтение и создание
файлов/каталогов без наследования этих прав на каталоги плееров. Установка службы
Player создаёт его отдельный каталог с закрытыми правами для LocalService,
SYSTEM и Administrators. Каталог MediaBoxVPlayer создаётся при первом запуске
от имени пользователя графической сессии; токен имеет отдельные закрытые права.
Каталоги данных сохраняются при удалении приложений.

Если конфигурация внешнего плеера отсутствует, расписания и медиаданные
размещаются в общем каталоге MediaBox. При первом запуске без новых данных
Manager копирует `project.json`, его журнал незавершённой операции, `timetable`,
`media`, `cron`, `nncronlt` и `mediabox.conf` из
первого найденного прежнего каталога MediaBoxManager, сохраняя
оригиналы. Пустые каталоги, созданные установщиком, не препятствуют переносу;
существующие новые файлы не перезаписываются. Ссылки конфигурации на файлы внутри
скопированных каталогов следуют за новым расположением, а внешние пути сохраняются.
После успешного переноса сохраняется отметка завершения: удалённые позднее файлы
не восстанавливаются из старого каталога. При ошибке перенос продолжается при
следующем запуске.

Для выбора существующей станции в Windows каталог данных
определяется значением `Path` в ключе `HKLM\SOFTWARE\MediaBox\Station`;
также поддерживается `C:\myplayer\mediabox.conf`. Это выбор каталога редактора,
а не канал управления MediaBoxPlayer. Сборка и автоматические тесты не требуют
установки MediaBoxPlayer. Команда
`MediaBoxManager.exe version` выводит версию приложения и сохраняет файл `version`
в текущей папке.

### Структура хранения данных и настроек

Ниже показана структура для Windows с каталогом станции по умолчанию.
`%ProgramData%` обычно соответствует `C:\ProgramData`. Каталоги плееров
и служебные файлы появляются по мере работы; `mediabox.conf` необязателен.

```text
%ProgramData%\MediaBox\
├── project.json                     # Музыкальные, видео- и рекламные расписания
├── project.json.lock                # Временная блокировка проекта
├── project.json.pending             # Журнал незавершённой операции с каталогами
├── mediabox.conf                    # Конфигурация станции, если задана
├── .station-storage-initialized      # Отметка завершения инициализации
├── .station-storage-migration        # Состояние незавершённого переноса данных
│
├── media\
│   ├── music\
│   │   └── <название канала>\
│   │       └── <аудиофайлы>
│   ├── video\
│   │   └── <название канала>\
│   │       └── <видеофайлы>
│   └── ads\
│       └── <рекламные файлы>
│
├── MediaBoxManager\
│   ├── MediaBoxManager.conf          # Настройки редактора, формат INI
│   ├── MediaBoxManager.log           # Журнал редактора
│   ├── managed-player\
│   │   └── <адрес>-<порт>\           # Аудиоплеер, запущенный Manager
│   │       ├── control.token        # При создании отдельного токена
│   │       ├── token.lock           # Временная блокировка создания токена
│   │       └── player.lock          # Блокировка на время работы плеера
│   └── managed-vplayer\
│       └── <адрес>-<порт>\           # Видеоплеер, запущенный Manager
│           ├── control.token        # При создании отдельного токена
│           ├── token.lock           # Временная блокировка создания токена
│           ├── player.lock          # Блокировка на время работы плеера
│           └── windows.json         # Видеоокна и загруженные очереди
│
├── MediaBoxPlayer\                  # При самостоятельном запуске
│   ├── control.token
│   └── player.lock
│
└── MediaBoxVPlayer\                 # При самостоятельном запуске
    ├── control.token
    ├── player.lock
    └── windows.json
```

Основные файлы содержат следующие данные:

| Файл | Формат и содержимое |
| --- | --- |
| `MediaBoxManager.conf` | INI. `FileFormats/AudioFormats` и `FileFormats/VideoFormats` — доступные форматы; `Appearance/style` и `Appearance/theme` — оформление; `Player` и `VideoPlayer` — параметры `Host`, `Port`, `Token`; `VideoPlayer/Profiles` — JSON-массив профилей экранов и именованных плейлистов |
| `mediabox.conf` | INI. Секция `mediastation`: `mediabox_id`, `mediabox_name`, `media`. Путь `media` может быть относительным к каталогу станции или абсолютным |
| `project.json` | JSON. `format: "mediabox.manager-project"`, `schemaVersion: 1`, массивы `music`, `video`, `advert`. Правила содержат UUID, имя, календарные условия и громкость; реклама — также режим выходов `timing` и назначенные минуты `preparedMinutes` |
| `project.json.pending` | JSON-журнал восстановления переименования каталога канала: секция, прежнее и новое имена, снимки проекта до и после операции |
| `windows.json` | JSON. `version: 1`, массив `windows`; каждое окно содержит `windowId`, `name`, `screen`, `fullscreen`, `paths`, `currentIndex`, `volumePercent`, `muted`, `repeat` |
| `control.token` | Текстовый токен доступа к TCP API соответствующего плеера |

Для автоматически запущенных плееров типичные имена каталогов —
`managed-player/127.0.0.1-17655` и `managed-vplayer/127.0.0.1-17656`.
Manager создаёт отдельный `control.token`, если токен не введён и стандартный
токен плеера недоступен. Аудиоплеер хранит очередь и параметры воспроизведения
в памяти; отдельного файла состояния у него нет.

После переноса в каталоге станции могут сохраняться прежние `timetable/`,
`cron/` и `nncronlt/`. В `timetable/` источниками импорта служат `timetable`,
`vtimetable`, `advertView` и `adverttable`; после переноса они не обновляются.
Рядом с медиафайлами могут оставаться `<имя файла>.tag` — старые INI-файлы
метаданных (`album`, `artist`, `title`, `genre`, `year`, `length`). Редактор
читает их при наличии, но не создаёт при просмотре медиатеки.

При выборе существующей станции `project.json`, `mediabox.conf` и данные
станции размещаются в её каталоге; расположение настроек Manager сохраняется.
Для самостоятельного запуска плееров каталог переопределяется через `--data-dir`.
В Linux общий корень — `/etc/mediabox`, а имена каталогов приложений записываются
строчными буквами. В Android корень — `files/mediabox` внутри закрытого каталога
соответствующего приложения; видеоплеер предназначен для Windows и Linux.

Пути определены в [StoragePaths](common/storagepaths.cpp), настройки — в
[Settings](src/settings.cpp) и [StationManager](src/stationmanager.cpp),
формат проекта — в [ProjectRepository](src/projectrepository.cpp), состояние
видеоокон — в [VideoService](MediaBoxVPlayer/src/videoservice.cpp).

### Подключение MediaBoxPlayer

**По расписанию:** на вкладке «Музыка» нажмите **По расписанию**. Manager
передаст актуальные правила, состав каналов и рекламу; плеер сам отслеживает
текущее время на своей машине и продолжает работать после закрытия Manager.
Изменения правил, импорт и удаление файлов обновляют снимок работающего
расписания. Календарь в «Проверке плана» предназначен для просмотра и не меняет
время исполнения. При пересечении активных каналов плеер сообщает о конфликте
и останавливает музыку; порядок строк не назначает приоритет.

**Вручную:** выберите канал и нажмите **Играть канал** в его карточке.
Все файлы канала запускаются по имени с повтором всей очереди и громкостью
канала независимо от календарных условий. Нажмите **По расписанию**, чтобы
вернуться к автоматическому режиму. Стоп, пауза и ручная замена очереди
отключают автоматический режим. Реклама исполняется только в режиме расписания;
после неё продолжается прерванный трек, если основной канал ещё действует.

Кнопка **Открыть папку** в медиатеке открывает локальную папку выбранного
музыкального или видеоканала. Размер, положение и развёрнутое состояние главного
окна восстанавливаются при следующем запуске. Снимок расписания хранится в
памяти плеера: после перезапуска самого плеера нужно снова нажать **По расписанию**.
Файлы должны быть доступны по переданным путям на машине плеера.

На Windows и Linux Manager сначала пробует подключиться к заданному адресу.
Если локальный плеер не запущен, Manager автоматически запускает соседний
`MediaBoxPlayer` в фоновом режиме `--managed` и подключается к нему по TCP.
Окно плеера и отдельное действие запуска не нужны. Для стандартного локального
подключения `127.0.0.1:17655` токен можно оставить пустым: Manager использует
доступный токен уже настроенного плеера либо создаёт токен своего экземпляра.
Если служба уже работает, а её токен недоступен текущему пользователю,
укажите полученный при настройке станции токен в настройках подключения.

Автозапуск работает только для `localhost` и IP-адресов loopback, при отказе
соединения или истечении времени TCP-подключения до обмена командами. Ошибка
токена или протокола не запускает другой экземпляр. Для удалённой машины плеер
нужно запустить отдельно; Android также сохраняет прежний запуск сервиса.

Для подключения к установленной службе или удалённому плееру:

1. Запустите плеер или установите его службу по [инструкции](MediaBoxPlayer/README.md).
2. В MediaBoxManager откройте **Настройки**, блок **MediaBoxPlayer**.
   Укажите адрес, порт (по умолчанию `127.0.0.1:17655`) и токен из
   `<data-dir>/control.token`, полученный при настройке станции. Сохраните подключение.
3. Откройте **Управление плеером** в нижней панели. Загрузите очередь из абсолютных
   путей **на машине плеера**, затем нажмите воспроизведение. Файлы должны быть
   заранее доступны учётной записи плеера; Manager их по TCP не передаёт.

Автоматический запуск использует адрес и порт выбранного подключения, а
блокировку процесса и собственный токен хранит в
`<каталог настроек Manager>/managed-player/<адрес>-<порт>`. Сохранённые адрес,
порт и токен подключения не меняются. Плеер продолжает работать после закрытия
Manager или отключения клиента; повторное подключение возвращает его текущее
состояние. Блокировка каталога и занятый адрес/порт защищают от второго
работающего экземпляра на той же точке подключения. Если рядом с Manager нет
исполняемого файла плеера или запуск не удался, Manager показывает ошибку.
После исправления причины нажмите **Подключить**, чтобы повторить запуск.

Панель поддерживает загрузку и добавление файлов, очистку очереди, play/pause/stop,
предыдущий и следующий файл, перемотку, громкость, mute и повтор. Действие
«На плеере…» в медиатеке после подтверждения заменяет всю очередь выбранным файлом
и запускает его. Возврата к прежней очереди нет. «Обновить состояние» только читает
текущее состояние: оно не отправляет расписание и не перезапускает службу.

Соединение и воспроизведение показываются отдельно. После потери связи последний
снимок помечается устаревшим, команды недоступны; воспроизведение на плеере может
продолжаться. Клиент переподключается и читает состояние, не восстанавливая очередь
и не повторяя изменяющие команды. Потерянный ответ на такую команду означает
неизвестный результат. Неверный токен или несовместимая версия останавливают
автоматические попытки до исправления настроек или явного подключения.

Параметры сохраняются штатным Settings в секции `Player` (`Host`, `Port`, `Token`).
Токен скрыт в поле ввода и не выводится в журналы; конфигурационный файл содержит
его в открытом виде и должен быть доступен только доверенным пользователям.
Контракт, ограничения сети и все команды описаны в [TCP_API.md](MediaBoxPlayer/TCP_API.md).

### Подключение MediaBoxVPlayer

На Windows и Linux Manager подключается к видеоплееру при запуске, даже если
панель видео ещё не открыта. Если локальный сервер недоступен, Manager запускает
соседний `MediaBoxVPlayer` с `--managed`. Для `localhost` и IP-адресов loopback
токен можно оставить пустым: он определяется автоматически. Неверный токен
или несовместимый протокол не вызывают запуск второго плеера; для удалённой
машины процесс нужно запустить заранее.

1. Для удалённого или самостоятельного плеера запустите `MediaBoxVPlayer`
   в пользовательской графической сессии на машине
   с подключёнными экранами. В Linux предварительно подготовьте каталог данных:
   `sudo install -d -m 700 -o "$(id -un)" -g "$(id -gn)" /etc/mediabox/mediaboxvplayer`.
   Для запуска без общесистемного каталога можно указать `--data-dir /путь/к/каталогу`.
2. В настройках MediaBoxManager задайте подключение к **MediaBoxVPlayer**:
   адрес, порт `17656` (по умолчанию `127.0.0.1:17656`). Для самостоятельного
   плеера укажите токен из его `<data-dir>/control.token`; для автоматического
   локального запуска оставьте поле пустым. Токен аудиоплеера не подходит.
3. Откройте вкладку **Видео → Видеоэкраны** либо действие **Настроить видеоэкраны
   и плейлисты** в настройках. Создайте логические экраны, назначьте каждому монитор
   из списка машины видеоплеера и нажмите **Применить окно**. Настройка
   **Запускать на весь экран** определяет начальный режим окна.
4. Создайте собственные плейлисты для каждого окна и нажмите **Загрузить плейлист
   в окно**. Пути к видео должны быть абсолютными и доступными на машине плеера;
   файлы по TCP не передаются.
5. Запустите нужный плейлист. Двойной щелчок по видео переключает полноэкранный
   режим и обычное окно; остальные видеоокна продолжают работать независимо.

Автоматический запуск использует отдельный каталог
`<каталог настроек Manager>/managed-vplayer/<адрес>-<порт>` для блокировки,
собственного токена и `windows.json`; сохранённые настройки подключения Manager
не меняются. Окна из этого каталога восстанавливаются без автоматического
воспроизведения. На порту `17656` при отсутствии собственного `windows.json`
Manager копирует его из стандартного каталога MediaBoxVPlayer, сохраняя оригинал.
После закрытия Manager или отключения клиента видеоплеер
продолжает работать. Если запуск не удался, устраните причину и повторно нажмите
**Сохранить подключение** в настройках MediaBoxVPlayer.

Профили экранов и именованные плейлисты Manager сохраняет в `VideoPlayer/Profiles`
своего конфига. Конфигурация окон и загруженные очереди сохраняются в `windows.json`
видеоплеера. Подключение видео отделено от подключения аудио.
MediaBoxVPlayer требует графическую сессию и не запускается как фоновая аудиослужба.
Установщик не добавляет его в автозагрузку. Настройка и протокол описаны в
[MediaBoxVPlayer/README.md](MediaBoxVPlayer/README.md) и
[MediaBoxVPlayer/TCP_API.md](MediaBoxVPlayer/TCP_API.md).

`cmake --install` создает папку `bin` с тремя приложениями и необходимыми библиотеками Qt.
Установщик создаётся через Inno Setup 6 командой `agent_build/build.ps1 -Installer`.
Скрипт включает развёртывание файлов и запускает `Installer/installer.iss`; готовый
файл находится в `Installer/bin/MediaBoxManager-<версия>-Setup.exe`. Версия берётся
из корневого `CMakeLists.txt`. Компилятор `ISCC.exe` должен быть в `PATH` или
стандартном каталоге Inno Setup 6; другой путь можно передать через
`-InnoSetupCompiler`. Установщик использует `agent_build/deploy/<конфигурация>`,
включает три приложения и предлагает запустить MediaBoxManager на последней странице.
Для MediaBoxVPlayer создаются отдельные ярлыки в меню «Пуск» и на рабочем столе.
Установка выполняется для всех пользователей в `C:\Program Files\MediaBox`
с запросом прав администратора. DLL среды MSVC устанавливаются рядом с приложениями;
дополнительный запуск системного `vc_redist.x64.exe` не требуется.
Для пересборки установщика из уже проверенной папки deploy есть отдельная команда
в [agent_build/README.md](agent_build/README.md); параметры и поведение установки
описаны в [Installer/README.md](Installer/README.md).

Единая эмблема лампочки используется установщиком и приложением.
`python Installer/prepare-artwork.py` экспортирует изображения мастера и значок
`src/icons/app.ico` для Windows EXE и Qt из `Installer/assets/emblem.png`
(для экспорта нужен Pillow).
