# MediaBoxManager

MediaBoxManager — редактор музыкальных и рекламных расписаний с управлением
фоновым аудиоплеером MediaBoxPlayer и многооконным видеоплеером MediaBoxVPlayer
по TCP. Для каждого видеоокна выбираются физический экран и отдельный плейлист.
Плееры поддерживают ручное воспроизведение; исполнение расписаний в их API
пока не реализовано. Все три приложения собираются через CMake на Qt 6 и C++23.

## Сборка в Windows

Текущая установленная версия Qt: **6.12.0**, комплект
`C:\Qt\6.12.0\msvc2022_64`. Для него нужен Visual Studio 2022 с компонентами
«Разработка классических приложений на C++» и Windows SDK. Сборка требует
CMake 3.28 или новее и Ninja; инструменты из `C:\Qt\Tools` подходят.

Из корня репозитория выполните в PowerShell:

```powershell
.\agent_build\build.ps1
```

Скрипт выбирает последнюю установленную версию Qt с комплектом MSVC x64
в `C:\Qt`, настраивает окружение компилятора, собирает Release и запускает CTest.
Результаты находятся в `agent_build\build\bin`: `MediaBoxManager.exe`,
`MediaBoxPlayer.exe`, `MediaBoxVPlayer.exe`; журналы — в `agent_build\logs`.

```powershell
# Сборка Debug и тесты
.\agent_build\build.ps1 -Configuration Debug

# Сборка, тесты и готовая папка с Qt DLL и плагинами
.\agent_build\build.ps1 -Deploy

# Сборка, тесты и установщик Inno Setup 6
.\agent_build\build.ps1 -Installer

# Явный выбор комплекта Qt
.\agent_build\build.ps1 -QtRoot C:\Qt -QtVersion 6.12.0 -QtKit msvc2022_64
```

Полный список параметров и дополнительные примеры находятся в
[agent_build/README.md](agent_build/README.md).

## CMake и Qt Creator

В Qt Creator откройте корневой `CMakeLists.txt` и выберите комплект Qt 6.12
MSVC 2022 x64. CMake автоматически обрабатывает `.ui`, Qt MOC, `.qrc` и
ресурс значка Windows. Стандарт C++23 обязателен; для установленного MSVC
CMake включает `/std:c++latest`.

Можно использовать CMake напрямую из **x64 Native Tools Command Prompt for VS 2022**
с CMake и Ninja в `PATH`:

```powershell
cmake -S . -B agent_build/build -G Ninja -DCMAKE_PREFIX_PATH=C:/Qt/6.12.0/msvc2022_64 -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build agent_build/build --parallel
ctest --test-dir agent_build/build --output-on-failure
cmake --install agent_build/build --prefix agent_build/deploy/Release
```

CTest настраивает путь к DLL Qt автоматически. Для ручного запуска исполняемых
файлов из папки сборки добавьте `C:\Qt\6.12.0\msvc2022_64\bin` в `PATH`.
Основной скрипт настраивает этот путь автоматически. Для генераторов с несколькими
конфигурациями добавьте `--config Release` к сборке и установке и `-C Release` к CTest.

Тесты проверяют редакторы расписания, кириллицу в именах каналов и аудиофайлов,
чтение и запись метаданных TagLib, ресурсы интерфейса, распределение рекламы
и команду версии. Текстовые отчёты QtTest сохраняются в `agent_build/build/tests`.

## Зависимости

Qt-компоненты MediaBoxManager: Core, Gui, Widgets, Xml, Network; MediaBoxPlayer
использует Core, Network, Multimedia. Для MediaBoxVPlayer нужны Core, Gui,
Widgets, Network, Multimedia и MultimediaWidgets. При `BUILD_TESTING=ON`
также нужен Test.
Исходный код приложения и тесты используют C++23 без расширений компилятора.

TagLib **1.13.1** собирается статически через CMake FetchContent из
[официального архива](https://github.com/taglib/taglib/releases/tag/v1.13.1),
проверяемого по SHA-256. Эта версия сохраняет совместимость с используемым API
TagLib 1.x. Первый запуск конфигурации требует интернета; последующие используют
кэш в каталоге сборки. Старые локальные копии `src/taglib` для сборки не нужны.
Внешний zlib и C bindings TagLib отключены.

Для сборки без сети заранее распакуйте архив TagLib 1.13.1 и задайте
`-DLAMPBOX_TAGLIB_SOURCE_DIR=C:/deps/taglib-1.13.1` при конфигурации CMake.

## Запуск

MediaBoxManager запускается без проверки установки и предложения скачать LampPlayer.
Настройки приложений отделены от общих файлов станции:

| Платформа | MediaBoxManager: настройки | MediaBoxPlayer: настройки | Общие файлы |
| --- | --- | --- | --- |
| Windows | `%ProgramData%\MediaBox\MediaBoxManager` | `%ProgramData%\MediaBox\MediaBoxPlayer` | `%ProgramData%\MediaBox` |
| Linux | `/etc/mediabox/mediaboxmanager` | `/etc/mediabox/mediaboxplayer` | `/etc/mediabox` |
| Android | `files/mediabox/mediaboxmanager` | `files/mediabox/mediaboxplayer` | `files/mediabox` внутри своего приложения |

MediaBoxVPlayer хранит собственные `control.token`, `windows.json` и блокировку
`player.lock` в `%ProgramData%\MediaBox\MediaBoxVPlayer` (Windows) или
`/etc/mediabox/mediaboxvplayer` (Linux). Параметр `--data-dir` позволяет выбрать
другой каталог. Многооконный видеоплеер предназначен для настольной графической
сессии Windows/Linux; таблица путей Android относится к Manager и аудиоплееру.

В Linux каталоги общесистемные: перед первым запуском администратор
[подготавливает их](MediaBoxPlayer/deploy/linux/README.md) для пользователя,
запускающего Manager и аудиосессию Player. Журналы Manager сохраняются в
`/etc/mediabox/mediaboxmanager`, токен и блокировка Player — в
`/etc/mediabox/mediaboxplayer`. Если каталоги недоступны для записи, приложение
сообщает об ошибке; перехода на пользовательские пути XDG нет. Прежние настройки
и данные текущего пользователя используются только как источники переноса.
В Android `files` — закрытый каталог приложения; разные APK не получают доступ
к каталогам друг друга. В Windows и Android журналы Manager хранятся в его каталоге.

Manager хранит `MediaBoxManager.conf` в своём каталоге настроек независимо от
места запуска EXE. При первом запуске он копирует прежний конфиг, только если
нового ещё нет. Приоритет источников в Windows:
`%ProgramData%\MediaBox\MediaBoxManager.conf`, прежний
`QStandardPaths::AppConfigLocation`, затем `MediaBoxManager.conf` и `lampbox.conf`
рядом с приложением. На остальных платформах проверяются те же источники без
Windows ProgramData. Исходный конфиг сохраняется; режим хранения настроек рядом
с EXE больше не выбирается автоматически.

Установщик Windows предоставляет обычным пользователям изменение каталога
Manager и общих каталогов станции. В корне MediaBox разрешены чтение и создание
файлов/каталогов без наследования этих прав на каталоги плееров. Установка службы
Player создаёт его отдельный каталог с закрытыми правами для LocalService,
SYSTEM и Administrators. Каталог MediaBoxVPlayer создаётся при первом запуске
от имени пользователя графической сессии; токен имеет отдельные закрытые права.
Каталоги данных сохраняются при удалении приложений.

Если конфигурация внешнего плеера отсутствует, расписания и медиаданные
размещаются в общем каталоге MediaBox. При первом запуске без новых данных
Manager копирует `timetable`, `media`, `cron`, `nncronlt` и `mediabox.conf` из
первого найденного прежнего каталога MediaBoxManager или `lampbox`, сохраняя
оригиналы. Пустые каталоги, созданные установщиком, не препятствуют переносу;
существующие новые файлы не перезаписываются. Ссылки конфигурации на файлы внутри
скопированных каталогов следуют за новым расположением, а внешние пути сохраняются.
После успешного переноса сохраняется отметка завершения: удалённые позднее файлы
не восстанавливаются из старого каталога. При ошибке перенос продолжается при
следующем запуске.

Для работы с существующими расписаниями LampPlayer в Windows каталог данных
по-прежнему определяется значением `Path` в ключе `HKLM\SOFTWARE\LampBox\Station`;
также поддерживается `C:\myplayer\mediabox.conf`. Это выбор каталога редактора,
а не канал управления MediaBoxPlayer. Сборка и автоматические тесты не требуют
установки LampPlayer. Команда
`MediaBoxManager.exe version` выводит версию приложения и сохраняет файл `version`
в текущей папке.

### Подключение MediaBoxPlayer

1. Запустите плеер или установите его службу по [инструкции](MediaBoxPlayer/README.md).
2. В MediaBoxManager откройте **Настройки**, блок **MediaBoxPlayer**.
   Укажите адрес, порт (по умолчанию `127.0.0.1:17655`) и токен из
   `<data-dir>/control.token`, полученный при настройке станции. Сохраните подключение.
3. Откройте **Управление плеером** в нижней панели. Загрузите очередь из абсолютных
   путей **на машине плеера**, затем нажмите воспроизведение. Файлы должны быть
   заранее доступны учётной записи плеера; Manager их по TCP не передаёт.

Панель поддерживает загрузку и добавление файлов, очистку очереди, play/pause/stop,
предыдущий и следующий файл, перемотку, громкость, mute и повтор. Действие
«На плеере…» в медиатеке после подтверждения заменяет всю очередь выбранным файлом
и запускает его. Возврата к прежней очереди нет. «Обновить состояние» только читает
текущее состояние: оно не отправляет расписание и не перезапускает службу.

Соединение и воспроизведение показываются отдельно. После потери связи последний
снимок помечается устаревшим, команды недоступны; воспроизведение на плеере может
продолжаться. Клиент переподключается и читает состояние, не восстанавливая очередь
и не повторяя изменяющие команды. Потерянный ответ на такую команду означает
неизвестный результат. Неверный токен или несовместимая версия останавливают
автоматические попытки до исправления настроек или явного подключения.

Параметры сохраняются штатным Settings в секции `Player` (`Host`, `Port`, `Token`).
Токен скрыт в поле ввода и не выводится в журналы; конфигурационный файл содержит
его в открытом виде и должен быть доступен только доверенным пользователям.
Контракт, ограничения сети и все команды описаны в [TCP_API.md](MediaBoxPlayer/TCP_API.md).

### Подключение MediaBoxVPlayer

1. Запустите `MediaBoxVPlayer` в пользовательской графической сессии на машине
   с подключёнными экранами. В Linux предварительно подготовьте каталог данных:
   `sudo install -d -m 700 -o "$(id -un)" -g "$(id -gn)" /etc/mediabox/mediaboxvplayer`.
   Для запуска без общесистемного каталога можно указать `--data-dir /путь/к/каталогу`.
2. В настройках MediaBoxManager задайте подключение к **MediaBoxVPlayer**:
   адрес, порт `17656` (по умолчанию `127.0.0.1:17656`) и токен из его
   `<data-dir>/control.token`. Токен аудиоплеера для этого подключения не подходит.
3. Откройте вкладку **Видео → Видеоэкраны** либо действие **Настроить видеоэкраны
   и плейлисты** в настройках. Создайте логические экраны, назначьте каждому монитор
   из списка машины видеоплеера и нажмите **Применить окно**. Настройка
   **Запускать на весь экран** определяет начальный режим окна.
4. Создайте собственные плейлисты для каждого окна и нажмите **Загрузить плейлист
   в окно**. Пути к видео должны быть абсолютными и доступными на машине плеера;
   файлы по TCP не передаются.
5. Запустите нужный плейлист. Двойной щелчок по видео переключает полноэкранный
   режим и обычное окно; остальные видеоокна продолжают работать независимо.

Профили экранов и именованные плейлисты Manager сохраняет в `VideoPlayer/Profiles`
своего конфига. Конфигурация окон и загруженные очереди сохраняются в `windows.json`
видеоплеера. Подключение видео отделено от подключения аудио.
MediaBoxVPlayer требует графическую сессию и не запускается как фоновая аудиослужба.
Установщик не добавляет его в автозагрузку. Настройка и протокол описаны в
[MediaBoxVPlayer/README.md](MediaBoxVPlayer/README.md) и
[MediaBoxVPlayer/TCP_API.md](MediaBoxVPlayer/TCP_API.md).

`cmake --install` создает папку `bin` с тремя приложениями и необходимыми библиотеками Qt.
Установщик создаётся через Inno Setup 6 командой `agent_build/build.ps1 -Installer`.
Скрипт включает развёртывание файлов и запускает `Installer/installer.iss`; готовый
файл находится в `Installer/bin/MediaBoxManager-<версия>-Setup.exe`. Версия берётся
из корневого `CMakeLists.txt`. Компилятор `ISCC.exe` должен быть в `PATH` или
стандартном каталоге Inno Setup 6; другой путь можно передать через
`-InnoSetupCompiler`. Установщик использует `agent_build/deploy/<конфигурация>`,
включает три приложения и предлагает запустить MediaBoxManager на последней странице.
Для MediaBoxVPlayer создаются отдельные ярлыки в меню «Пуск» и на рабочем столе.
Установка выполняется для всех пользователей в `C:\Program Files\MediaBox`
с запросом прав администратора. DLL среды MSVC устанавливаются рядом с приложениями;
дополнительный запуск системного `vc_redist.x64.exe` не требуется.
Для пересборки установщика из уже проверенной папки deploy есть отдельная команда
в [agent_build/README.md](agent_build/README.md); параметры и поведение установки
описаны в [Installer/README.md](Installer/README.md).

Единая эмблема лампочки используется установщиком и приложением.
`python Installer/prepare-artwork.py` экспортирует изображения мастера и значок
`src/icons/app.ico` для Windows EXE и Qt из `Installer/assets/emblem.png`
(для экспорта нужен Pillow).
